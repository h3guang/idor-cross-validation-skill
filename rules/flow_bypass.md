# 流程绕过检测规则（完整版）

## 规则描述
检测多步骤业务流程中是否存在步骤跳过或伪造。

## 检测项

### 1. 支付流程跳过
- 直接访问确认页 /checkout/confirm
- 跳过支付状态更新
- 直接调用发货接口

### 2. 多步骤注册绕过
- 跳过邮箱/手机验证
- 直接设置密码
- 跳过实名认证

### 3. 支付回调伪造
- 伪造支付成功通知
- 签名绕过或缺失
- 重复发送回调

### 4. 业务流程顺序颠倒
- 退款后继续使用服务
- 审批前执行操作
- 签约前访问付费内容

## 判断标准
- 跳过步骤直接访问成功
- 伪造回调成功（无签名验证）
- 逆向流程执行成功

## 测试用例示例
POST /api/payment/webhook
{
  "order_id": "12345",
  "status": "paid",
  "signature": "fake_signature"
}

预期: 验证签名失败，返回403
实际: 200 OK，订单标记为已支付 → 漏洞确认

## 修复建议
- 状态机严格校验（只能按顺序转换）
- 回调添加强签名验证（HMAC/RSA）
- 流程完整性检查
- 关键步骤记录审计日志
- 回调防重放（时间戳+nonce）
